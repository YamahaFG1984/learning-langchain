第 01 章

LLM 基础与 LangChain 构建块

大模型只做一件事：给它一段文本，它接着往下写。整本书剩下的内容，都是在解决「怎么把该给的东西给它，怎么把它吐出来的东西收好」。这一章先认零件。

读完这一章你会

  • 说清楚 LLM 接口和 ChatModel 接口的区别，以及三种消息角色各干什么
  • 用 PromptTemplate / ChatPromptTemplate 把提示词变成可复用的「配方」
  • 用 with_structured_output 让模型稳定吐出 JSON
  • 理解 Runnable 的 invoke / batch / stream 三件套，并在命令式和 LCEL 之间做出选择

问题在哪里

把 LLM 塞进应用里，难的从来不是「调用 API」。难的是两头：进去的提示怎么拼，出来的文本怎么用。模型本身是中间那个黑盒，你改不了；你能改的只有它的左右两侧。

两个接口：LLM 与聊天模型

LangChain 给模型提供了两套接口。LLM 是「字符串进、字符串出」；ChatModel 是「消息列表进、一条消息出」。

今天你几乎只会用聊天模型。原书里演示 OpenAI（文本补全）接口时用的是 gpt-3.5-turbo，其实那个模型走的是 chat API；纯补全接口现在只剩 gpt-3.5-turbo-instruct 还在用。所以本仓库的示例统一用 ChatOpenAI。

三种角色

类角色用来放什么
SystemMessagesystem你（开发者）给模型的行为指令。用户看不到，但对输出影响极大。
HumanMessageuser用户的问题，以及你塞进去的检索结果等上下文。
AIMessageassistant模型生成的内容。也是工具调用请求的载体（第 6 章）。
ToolMessagetool工具执行结果，必须紧跟在发起调用的 AIMessage 之后。
ch1/{py,js}/c-system 
from langchain_core.messages import HumanMessage, SystemMessage
from langchain_openai.chat_models import ChatOpenAI

model = ChatOpenAI(model="gpt-4.1-mini")

system_msg = SystemMessage(
    "You are a helpful assistant that responds to questions with three exclamation marks."
)
human_msg = HumanMessage("What is the capital of France?")

response = model.invoke([system_msg, human_msg])
print(response.content)
# Paris!!!
import { ChatOpenAI } from '@langchain/openai';
import { HumanMessage, SystemMessage } from '@langchain/core/messages';

const model = new ChatOpenAI({ model: 'gpt-4.1-mini' });

const prompt = [
  new SystemMessage(
    'You are a helpful assistant that responds to questions with three exclamation marks.'
  ),
  new HumanMessage('What is the capital of France?'),
];

const response = await model.invoke(prompt);
console.log(response.content);
// Paris!!!

两个最常调的参数

temperature 控制随机性：结构化输出、路由判断用 0–0.1；创意写作用 0.7+。max_tokens 控制输出长度上限，也就是控制成本；调太小会看到答案被硬生生截断。

让提示词可复用：提示模板

提示词里通常有一部分是固定的（指令、格式要求），一部分是变的（用户问题、检索到的上下文）。模板就是把这两部分分开：模板是配方，invoke 之后才是一份具体的提示。

做聊天应用时用 ChatPromptTemplate，可以按角色分别设定模板：

ch1/{py,js}/g-chat-prompt-model 
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai.chat_models import ChatOpenAI

# template 和 model 都可以复用很多次
template = ChatPromptTemplate.from_messages([
    ("system", '根据下面的上下文回答问题。若无法回答，就说 "I don\'t know"。'),
    ("human", "Context: {context}"),
    ("human", "Question: {question}"),
])

model = ChatOpenAI(model="gpt-4.1-mini")

prompt = template.invoke({"context": "...", "question": "Which model providers offer LLMs?"})
print(model.invoke(prompt).content)
import { ChatPromptTemplate } from '@langchain/core/prompts';
import { ChatOpenAI } from '@langchain/openai';

const template = ChatPromptTemplate.fromMessages([
  ['system', '根据下面的上下文回答问题。若无法回答，就说 "I don\'t know"。'],
  ['human', 'Context: {context}'],
  ['human', 'Question: {question}'],
]);

const model = new ChatOpenAI({ model: 'gpt-4.1-mini' });

const prompt = await template.invoke({ context: '...', question: 'Which model providers offer LLMs?' });
console.log((await model.invoke(prompt)).content);

易踩的坑

模板默认用 f-string 语法，{} 里的东西会被当成变量。如果你的提示里本身要出现花括号（比如举 JSON 例子），要写成 {{ 和 }} 转义，否则会报缺少变量。

让模型吐出 JSON

纯文本适合给人看，不适合给代码看。当 LLM 只是你系统里的一环时，你需要它输出符合你定义的 schema 的结构化数据。

with_structured_output() 一行搞定这件事，它背后做了两件事：把你的 Pydantic / Zod 模型转成 JSON Schema 发给模型（走 function calling 或 JSON mode），再用同一个 schema 校验返回值。校验不过会直接报错，而不是把脏数据传下去。

ch1/{py,js}/h-structured 
from langchain_openai import ChatOpenAI
from pydantic import BaseModel, Field


class AnswerWithJustification(BaseModel):
    """An answer to the user's question along with justification."""

    answer: str = Field(description="给用户的答案")
    justification: str = Field(description="给出这个答案的理由")


llm = ChatOpenAI(model="gpt-4.1-mini", temperature=0)
structured_llm = llm.with_structured_output(AnswerWithJustification)

print(structured_llm.invoke("一磅砖头和一磅羽毛哪个重？"))
# AnswerWithJustification(answer='一样重', justification='都是一磅…')
import { ChatOpenAI } from '@langchain/openai';
import { z } from 'zod';

const answerSchema = z
  .object({
    answer: z.string().describe('给用户的答案'),
    justification: z.string().describe('给出这个答案的理由'),
  })
  .describe("An answer to the user's question along with justification.");

const model = new ChatOpenAI({ model: 'gpt-4.1-mini', temperature: 0 })
  .withStructuredOutput(answerSchema);

console.log(await model.invoke('一磅砖头和一磅羽毛哪个重？'));

1.x 变更

书上写的是 from langchain_core.pydantic_v1 import BaseModel。这个兼容层已经删除了，现在直接 from pydantic import BaseModel, Field。另外注意：Field(description=...) 里的描述不是注释，是给模型看的提示——写清楚了准确率会明显提高。

如果你要的不是 JSON 而是 CSV、XML 之类，用输出解析器（Output Parser）。它同样是个 Runnable，可以直接接在模型后面：

ch1/{py,js}/i-csv 
from langchain_core.output_parsers import CommaSeparatedListOutputParser

parser = CommaSeparatedListOutputParser()
print(parser.invoke("apple, banana, cherry"))
# ['apple', 'banana', 'cherry']
import { CommaSeparatedListOutputParser } from '@langchain/core/output_parsers';

const parser = new CommaSeparatedListOutputParser();
console.log(await parser.invoke('apple, banana, cherry'));
// ['apple', 'banana', 'cherry']

Runnable：所有零件长得一样

你可能已经注意到了：模型、模板、解析器，全都用 invoke。这不是巧合——它们都实现了同一个 Runnable 接口。学会一个，就等于学会全部。

方法输入 → 输出什么时候用
invoke一个 → 一个默认选择
batch一批 → 一批多条独立输入，会自动并发（第 3 章多查询检索靠它）
stream一个 → 逐块产出要让用户尽快看到第一个字
ainvoke / abatch / astream同上，异步版Python 里在 async 上下文中使用；JS 本来就是异步的

拼装：命令式还是声明式

把零件连起来有两条路。它们产出的东西用法完全一样（都是 Runnable，都能 invoke），区别在于你写多少代码、以及框架能帮你做多少。

ch1/{py,js}/k-imperative · l-declarative 
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import chain
from langchain_openai.chat_models import ChatOpenAI

template = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful assistant."),
    ("human", "{question}"),
])
model = ChatOpenAI(model="gpt-4.1-mini")

# ① 命令式：@chain 把任意函数变成 Runnable
@chain
def chatbot(values):
    prompt = template.invoke(values)
    return model.invoke(prompt)

# ② 声明式：| 就是「把左边的输出喂给右边」
chatbot_lcel = template | model

# 用法完全一样
chatbot.invoke({"question": "谁提供 LLM 服务？"})
chatbot_lcel.invoke({"question": "谁提供 LLM 服务？"})
import { ChatPromptTemplate } from '@langchain/core/prompts';
import { RunnableLambda } from '@langchain/core/runnables';
import { ChatOpenAI } from '@langchain/openai';

const template = ChatPromptTemplate.fromMessages([
  ['system', 'You are a helpful assistant.'],
  ['human', '{question}'],
]);
const model = new ChatOpenAI({ model: 'gpt-4.1-mini' });

// ① 命令式：RunnableLambda 把任意函数变成 Runnable
const chatbot = RunnableLambda.from(async (values) => {
  const prompt = await template.invoke(values);
  return await model.invoke(prompt);
});

// ② 声明式：pipe 就是「把左边的输出喂给右边」
const chatbotLcel = template.pipe(model);

await chatbot.invoke({ question: '谁提供 LLM 服务？' });
await chatbotLcel.invoke({ question: '谁提供 LLM 服务？' });
命令式声明式（LCEL）
语法普通 Python / JS| / .pipe()
并行自己开线程 / Promise.all自动
流式自己 yield自动
异步自己写 async 版本自动

承上启下

从第 4 章开始，本书会把主力从 LCEL 切到 LangGraph。原因很简单：LCEL 擅长「一条直线」，而真实应用有循环、有分支、有需要保存下来的中间状态。LCEL 并没有被废弃——它仍然是拼装单个步骤的最佳工具，只是不再负责整体编排。

动手练一练

  1. 把 ch1/py/l-declarative.py 的 ChatOpenAI() 换成 temperature=1.2，连跑三次，观察输出差异；再换回 0，看看是否稳定。
  2. 给 h-structured.py 的 schema 加一个 confidence: float 字段，写好 description，看模型是否会填。
  3. 把 k-imperative.py 里的 return model.invoke(prompt) 改成 for token in model.stream(prompt): yield token，再用 chatbot.stream(...) 调用——这就是命令式下手动支持流式的样子。
