第 04 章

用 LangGraph 给机器人加记忆

大模型是无状态的：每次调用它都不记得上一次说过什么。所谓「记忆」，其实就是你每次都把之前的对话重新递给它。这一章讲怎么把这件事做得靠谱——并顺便认识贯穿后半本书的 LangGraph。

读完这一章你会

  • 理解「记忆」的本质，以及朴素做法在生产中会碰到的四个问题
  • 用 StateGraph 的状态 / 节点 / 边三件套搭出第一个图
  • 用 checkpointer + thread_id 让多个用户的对话互不串台
  • 用 trim / filter / merge 三个工具整理聊天记录

记忆的本质：把历史再发一遍

先看最朴素的版本。("placeholder", "{messages}") 是一个可以塞进任意条消息的占位槽：

ch4/{py,js}/a-simple-memory 
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI

prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful assistant. Answer all questions to the best of your ability."),
    ("placeholder", "{messages}"),      # ← 整段历史插在这里
])

chain = prompt | ChatOpenAI(model="gpt-4.1-mini")

response = chain.invoke({
    "messages": [
        ("human", "Translate this sentence from English to French: I love programming."),
        ("ai", "J'adore programmer."),
        ("human", "What did you just say?"),   # ← 靠前两条才能回答
    ],
})
print(response.content)
import { ChatPromptTemplate } from '@langchain/core/prompts';
import { ChatOpenAI } from '@langchain/openai';

const prompt = ChatPromptTemplate.fromMessages([
  ['system', 'You are a helpful assistant. Answer all questions to the best of your ability.'],
  ['placeholder', '{messages}'],
]);

const chain = prompt.pipe(new ChatOpenAI({ model: 'gpt-4.1-mini' }));

const response = await chain.invoke({
  messages: [
    ['human', 'Translate this sentence from English to French: I love programming.'],
    ['ai', "J'adore programmer."],
    ['human', 'What did you just say?'],
  ],
});
console.log(response.content);

能跑。但把它放到生产环境，四个问题立刻冒出来：

问题 1

更新必须是原子的

「记录了问题但没记录回答」这种半截状态会让下一轮彻底错乱。

问题 2

要存在持久介质里

进程一重启，内存里的对话就没了。

问题 3

要能挑选

存哪些、发哪些，得能分开控制，否则上下文窗口迟早爆。

问题 4

要能在 LLM 之外检查和修改

调试、人工介入、撤销重来，都要求状态是可读可写的。

LangGraph：三个词

LangGraph 官方的自我介绍是：「用于实现多参与者、多步骤、有状态认知架构的库」。这三个词拆开看就很好懂。

搭第一个图

一个图由三样东西构成：

要素是什么写法
State贯穿全程的数据结构。定义有哪些字段，以及每个字段怎么合并更新。TypedDict + Annotated（JS 用 Annotation.Root）
Node一步工作。就是个普通函数：收 state，返回「对 state 的更新」。builder.add_node("name", fn)
Edge节点之间的连线。可以是固定的，也可以是条件的。add_edge / add_conditional_edges

最容易搞混的一点：reducer

messages: Annotated[list, add_messages] 里的 add_messages 叫 reducer，它决定「新值怎么和旧值合并」。没有 reducer 的字段是覆盖，有 add_messages 的字段是追加。所以节点只需要返回新产生的那一条消息，而不用返回整个列表。

add_messages 还额外做一件事：如果新消息的 id 和已有消息相同，就替换而不是追加——第 8 章「编辑状态」靠的就是这个性质。

ch4/{py,js}/b-state-graph 
from typing import Annotated, TypedDict

from langchain_core.messages import HumanMessage
from langchain_openai import ChatOpenAI
from langgraph.graph import END, START, StateGraph, add_messages


# ① 状态：messages 用 add_messages 合并（追加而非覆盖）
class State(TypedDict):
    messages: Annotated[list, add_messages]


model = ChatOpenAI(model="gpt-4.1-mini")


# ② 节点：收 state，返回「状态更新」
def chatbot(state: State):
    answer = model.invoke(state["messages"])
    return {"messages": [answer]}      # 只返回新增的那条


builder = StateGraph(State)
builder.add_node("chatbot", chatbot)

# ③ 边：从哪开始、到哪结束
builder.add_edge(START, "chatbot")
builder.add_edge("chatbot", END)

graph = builder.compile()      # 编译后就是个 Runnable：invoke / stream / batch 都有

for chunk in graph.stream({"messages": [HumanMessage("hi!")]}):
    print(chunk)
# {'chatbot': {'messages': [AIMessage('How can I help you?')]}}
import {
  StateGraph, Annotation, messagesStateReducer, START, END,
} from '@langchain/langgraph';
import { HumanMessage } from '@langchain/core/messages';
import { ChatOpenAI } from '@langchain/openai';

// ① 状态
const StateAnnotation = Annotation.Root({
  messages: Annotation({ reducer: messagesStateReducer, default: () => [] }),
});

const model = new ChatOpenAI({ model: 'gpt-4.1-mini' });

// ② 节点
async function chatbot(state) {
  const answer = await model.invoke(state.messages);
  return { messages: [answer] };
}

// ③ 边
const graph = new StateGraph(StateAnnotation)
  .addNode('chatbot', chatbot)
  .addEdge(START, 'chatbot')
  .addEdge('chatbot', END)
  .compile();

for await (const chunk of await graph.stream({ messages: [new HumanMessage('hi!')] })) {
  console.log(chunk);
}

把图画出来

graph.get_graph().draw_mermaid_png()（JS：await graph.getGraph().drawMermaidPng()）能直接生成结构图。图一复杂就非常有用——尤其是第 5–7 章的条件边，画出来一眼就能看出有几条路径。

让它真的记住：checkpointer 与 thread

上面的图每次调用都从空白开始。加一个 checkpointer（存储适配器），它会在每一步结束后保存一次状态。下次调用同一个 thread_id 时，图先把上次的状态读回来，和新输入合并，再开始执行。

ch4/{py,js}/c-persistent-memory 
from langgraph.checkpoint.memory import InMemorySaver

graph = builder.compile(checkpointer=InMemorySaver())

thread1 = {"configurable": {"thread_id": "1"}}

graph.invoke({"messages": [HumanMessage("hi, my name is Jack!")]}, thread1)
graph.invoke({"messages": [HumanMessage("what is my name?")]}, thread1)
# → "Your name is Jack"

# 状态是可读可写的
print(graph.get_state(thread1))
graph.update_state(thread1, {"messages": [HumanMessage("I like LLMs!")]})
import { MemorySaver } from '@langchain/langgraph';

const graph = builder.compile({ checkpointer: new MemorySaver() });

const thread1 = { configurable: { thread_id: '1' } };

await graph.invoke({ messages: [new HumanMessage('hi, my name is Jack!')] }, thread1);
await graph.invoke({ messages: [new HumanMessage('what is my name?')] }, thread1);

console.log(await graph.getState(thread1));
await graph.updateState(thread1, { messages: [new HumanMessage('I like LLMs!')] });

1.x 变更

Python 的 MemorySaver 已更名为 InMemorySaver（旧名保留为别名，但新代码用新名）。JS 侧仍然叫 MemorySaver。

Checkpointer适用场景Python 包
InMemorySaver本地实验、单元测试。进程退出即丢失。内置
SqliteSaver本地应用、小规模部署。langgraph-checkpoint-sqlite
PostgresSaver生产。LangGraph Platform 默认用这个。langgraph-checkpoint-postgres

整理聊天记录：裁剪、过滤、合并

历史会越长越长，而上下文窗口是有限的、按 token 计费的、而且塞太多还会分散模型注意力。三个工具对应三种整理需求：

ch4/{py,js}/d-trim-messages · e-filter · f-merge 
from langchain_core.messages import (
    AIMessage, HumanMessage, SystemMessage,
    filter_messages, merge_message_runs, trim_messages,
)
from langchain_openai import ChatOpenAI

# ① 裁剪：留最近的、不超过 65 token
trimmer = trim_messages(
    max_tokens=65,
    strategy="last",                                # "last" 留最近，"first" 留最早
    token_counter=ChatOpenAI(model="gpt-4.1-mini"),  # 用哪个模型的分词器数 token
    include_system=True,                            # 系统提示永远保留
    allow_partial=False,                            # 不切半条消息
    start_on="human",                                # 结果必须从 human 开始
)
print(trimmer.invoke(messages))

# ② 过滤：按类型 / 名字 / id
print(filter_messages(messages, include_types="human"))
print(filter_messages(messages, exclude_names=["example_user", "example_assistant"]))
print(filter_messages(messages, include_types=[HumanMessage, AIMessage], exclude_ids=["3"]))

# ③ 合并连续同类型
print(merge_message_runs(messages))

# 三者都能直接接进链里（不传 messages 参数时返回一个 Runnable）
chain = trim_messages(max_tokens=65, strategy="last", token_counter=model) | model
import {
  AIMessage, HumanMessage, SystemMessage,
  filterMessages, mergeMessageRuns, trimMessages,
} from '@langchain/core/messages';
import { ChatOpenAI } from '@langchain/openai';

const trimmer = trimMessages({
  maxTokens: 65,
  strategy: 'last',
  tokenCounter: new ChatOpenAI({ model: 'gpt-4.1-mini' }),
  includeSystem: true,
  allowPartial: false,
  startOn: 'human',
});
console.log(await trimmer.invoke(messages));

console.log(filterMessages(messages, { includeTypes: ['human'] }));
console.log(filterMessages(messages, { excludeNames: ['example_user', 'example_assistant'] }));
console.log(mergeMessageRuns(messages));

start_on="human" 为什么重要

如果裁剪后第一条是 AIMessage，模型会看到一个「凭空出现的回答」，很容易被带偏。更严重的是工具调用场景：一条请求调用工具的 AIMessage 后面必须紧跟对应的 ToolMessage，裁断了会直接被 API 拒绝。

小结

记住这个

记忆 = 状态 + 存储 + 线程

状态定义存什么，checkpointer 决定存到哪，thread_id 决定存给谁。

记住这个

节点返回的是「更新」

不是新的完整状态。合并规则由 reducer 决定，这是 LangGraph 最容易误解的一点。

记住这个

存的 ≠ 发的

checkpointer 可以存全量历史，发给模型前再用 trim / filter 挑一遍。

记住这个

状态是可检查、可修改的

get_state / update_state 是第 8 章所有人在环路能力的基础。
